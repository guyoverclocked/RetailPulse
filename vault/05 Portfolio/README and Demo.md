# README and demo

## Why

Most reviewers will spend minutes, not hours. The README must reveal the problem, evidence, and runnable path immediately.

## README order

1. One-sentence problem and business decision.
2. Architecture diagram and 60–90 second demo GIF.
3. Dataset, forecast horizon, prediction-time contract, and limitations.
4. Backtest design and model comparison table.
5. Forecast uncertainty and staffing scenario results.
6. Local quick start, tests, API routes, and cloud architecture.
7. Reproducibility, monitoring, license, and next steps.

Show real measured metrics; label simulated cost outcomes. Avoid a long technology inventory without explaining why each piece exists.

## Alternatives

A hosted write-up can add polish, but GitHub must remain complete on its own.

## Done when

A new reader can understand the value in 30 seconds and run the fixture demo in under 10 minutes.
