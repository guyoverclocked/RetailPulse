# How to Use This Vault

## Why

A large project becomes manageable when every session has one question, one output, and one stopping point.

## Method

- Begin each week at [[Progress Dashboard]].
- Open the current phase from [[Master Roadmap]].
- Read linked **Learn** notes before their matching **Build** notes.
- Do not mark a note complete until its **Done when** condition is true.
- Record modeling results in [[Experiment Record Template]].
- Record meaningful trade-offs in [[Decision Log]].
- End the week using [[Weekly Review Template]].

## Status convention

- `planned`: not started
- `active`: current work
- `blocked`: a named issue prevents progress
- `complete`: evidence exists
- `deferred`: intentionally removed from this release

## If you fall behind

Use [[Recovery and Scope Rules]]. Do not silently compress testing, backtesting, or documentation. Reduce challengers or cloud extras first.

## Orientation week

Aug 26-30 is a pre-roadmap orientation week. It sits before the formal commitment
window ([[Master Roadmap]], Aug 31) and covers only vault setup and the start-here
reading — no phase work is scheduled inside it.
